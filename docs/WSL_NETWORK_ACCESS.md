# Доступ к WSL2 из локальной сети

Это руководство поможет настроить доступ к frontend и backend, запущенным в WSL2, с других машин в локальной сети.

## Проблема

WSL2 использует виртуальную сеть, которая изолирована от локальной сети Windows. По умолчанию сервисы, запущенные в WSL2, доступны только с локальной машины через `localhost`.

## Решение

Есть два способа решить эту проблему:

### Способ 1: Mirrored Networking Mode (Рекомендуется) ⭐

**Преимущества:**
- Настраивается один раз
- Работает автоматически после перезапуска WSL
- Не требует обновления после изменения IP адреса WSL
- Более современное и надежное решение

**Шаги:**

1. **Настройка (один раз)**:
   ```powershell
   # Запустите PowerShell от имени администратора
   PowerShell -ExecutionPolicy Bypass -File scripts/setup-wsl-mirrored-networking.ps1
   ```

2. **Перезапустите WSL2**:
   ```powershell
   wsl --shutdown
   # Затем откройте WSL снова
   ```

3. **Запустите приложение**:
   ```bash
   ./start-demo-wsl.sh
   ```

4. **Узнайте IP адрес Windows хоста**:
   ```powershell
   # В PowerShell
   ipconfig | findstr IPv4
   ```

5. **Подключитесь с других машин**:
   - Frontend: `http://<IP_АДРЕС_WINDOWS>:3000`
   - Backend: `http://<IP_АДРЕС_WINDOWS>:8000`

### Способ 2: Port Forwarding

**Преимущества:**
- Работает сразу без перезапуска WSL
- Не требует изменения конфигурации WSL

**Недостатки:**
- Требуется запускать скрипт после каждого перезапуска WSL (если IP изменился)
- Менее надежное решение

**Шаги:**

1. **Настройка (запускайте после каждого перезапуска WSL, если IP изменился)**:
   ```powershell
   # Запустите PowerShell от имени администратора
   PowerShell -ExecutionPolicy Bypass -File scripts/setup-wsl-port-forwarding.ps1
   ```

2. **Запустите приложение**:
   ```bash
   ./start-demo-wsl.sh
   ```

3. **Подключитесь с других машин**:
   - Используйте IP адрес Windows хоста (указан в выводе скрипта)

## Проверка работы

### На машине с WSL:

1. Проверьте, что порты слушают на всех интерфейсах:
   ```bash
   # В WSL
   netstat -tuln | grep -E ':(3000|8000)'
   # Или
   ss -tuln | grep -E ':(3000|8000)'
   ```
   Должно быть видно `0.0.0.0:3000` и `0.0.0.0:8000`

2. Проверьте доступность с локальной машины:
   ```bash
   curl http://localhost:3000
   curl http://localhost:8000/health
   ```

### На другой машине в локальной сети:

1. Убедитесь, что обе машины в одной сети:
   ```bash
   # Проверьте, что IP адреса в одной подсети
   # Например: 192.168.1.x или 10.0.0.x
   ```

2. Проверьте доступность:
   ```bash
   # Замените <IP_WINDOWS> на IP адрес Windows хоста
   curl http://<IP_WINDOWS>:3000
   curl http://<IP_WINDOWS>:8000/health
   ```

3. Откройте в браузере:
   - `http://<IP_WINDOWS>:3000`

## Устранение проблем

### Проблема: Не могу подключиться с другой машины

**Решение:**

1. **Проверьте брандмауэр Windows**:
   - Скрипты автоматически настраивают брандмауэр
   - Если проблема остается, проверьте вручную:
     ```powershell
     Get-NetFirewallRule -DisplayName "*Astra Trainer*"
     ```

2. **Проверьте port forwarding** (если используете способ 2):
   ```powershell
   netsh interface portproxy show all
   ```
   Должны быть видны правила для портов 3000 и 8000

3. **Проверьте, что сервисы запущены**:
   ```bash
   # В WSL
   ps aux | grep -E '(uvicorn|react-scripts)'
   ```

4. **Проверьте IP адрес WSL** (для способа 2):
   ```bash
   # В WSL
   hostname -I
   ```
   Если IP изменился, запустите скрипт port forwarding снова

5. **Проверьте сетевые настройки**:
   - Убедитесь, что обе машины в одной локальной сети
   - Проверьте, что нет блокировки на уровне роутера
   - Убедитесь, что Windows не в режиме "Общедоступная сеть" (должна быть "Частная сеть")

### Проблема: После перезапуска WSL подключение не работает

**Решение:**

- **Для Mirrored Networking Mode**: Просто перезапустите WSL (`wsl --shutdown` и откройте снова)
- **Для Port Forwarding**: Запустите скрипт `setup-wsl-port-forwarding.ps1` снова

### Проблема: Порты заняты

**Решение:**

1. Найдите процесс, использующий порт:
   ```bash
   # В WSL
   sudo lsof -i :3000
   sudo lsof -i :8000
   ```

2. Остановите процесс или измените порты в конфигурации

## Дополнительная информация

- **Безопасность**: По умолчанию доступ разрешен только для частной сети. Для публичной сети потребуется дополнительная настройка брандмауэра.

- **Производительность**: Mirrored Networking Mode может иметь небольшое влияние на производительность сети, но обычно это незаметно.

- **IPv6**: Если ваша сеть использует IPv6, может потребоваться дополнительная настройка.
